# Plan: Downloadable LEGO Mosaic Instructions (PDF)

## Summary

Add a "Download Instructions" button that generates a PDF instruction booklet in the browser. The format follows the official LEGO Art mosaic instruction style: numbered colors inside a top-down grid, one baseplate section per page, with a cover, color legend, and bill of materials.

No external tools required. No server. The PDF is generated client-side using jsPDF with vector drawing (colored rectangles + text), keeping file sizes small (3-5 MB for a full booklet).

## Why PDF, not enhanced LDR

Mosaics are flat. 3D renders (what LPub3D produces from LDR STEP breaks) are worse than 2D grids for mosaic building. Official LEGO Art sets (31197, 31199, 31203) use pure 2D top-down numbered grids. We should match that format.

An enhanced LDR with granular `0 STEP` breaks + `0 !LPUB` meta-commands could be a secondary export for power users who have LPub3D. Low effort since the LDR generator already exists. But the primary deliverable is the PDF.

## Library

**jsPDF** (latest v4.x). ~300KB bundle, zero dependencies, MIT license.

Core API needed:
- `doc.setFillColor(r,g,b)` + `doc.rect(x,y,w,h,'F')` for colored tiles
- `doc.text()` for color numbers, headers, labels
- `doc.setDrawColor()` + `doc.rect(x,y,w,h,'S')` for grid lines
- `doc.addPage()` for multi-page booklet
- `doc.save()` or `doc.output('blob')` for download

Install: `npm install jspdf`

## Instruction Format

### Page Sequence

1. **Cover page** (1 page)
2. **Color legend** (1 page)
3. **Bill of materials** (1 page)
4. **Section pages** (1 per baseplate, each containing the full grid for that section)

### Page Counts by Mosaic Size

| Size | Baseplates | Section pages | Total pages |
|------|-----------|--------------|-------------|
| 16x16 | 1 | 1 | 4 |
| 32x32 | 1 | 1 | 4 |
| 48x48 | 1 | 1 | 4 |
| 64x64 | 4 (32x32) | 4 | 7 |
| 96x96 | 4 (48x48) | 4 | 7 |
| 96x96 | 9 (32x32) | 9 | 12 |

This is very manageable. One section page per baseplate keeps the booklet short while still being usable. Each cell in a 48-stud grid at A4 width is ~3.5mm, which fits a small number. For 16-stud and 32-stud grids the cells are larger and more comfortable.

If cells are too small for 48-stud baseplates, we could split each 48x48 baseplate into quadrants (4 pages of 24x24) or show the full grid with a supplementary zoomed strip per row group. Research suggests the full grid with numbers is sufficient at these sizes.

Key elements:
- **Section number** and baseplate type in header
- **Locator thumbnail** (top-right): small mosaic overview with current section highlighted
- **Numbered grid**: each cell contains the color number from the legend. Cells are filled with the actual color and the number is drawn in a contrasting color (white on dark, black on light).
- **Column numbers** across top, **row numbers** down left side
- **Per-section parts summary** at bottom

### Color Number Display

Each cell gets the actual LEGO color as fill, with the color number drawn inside. For readability:
- Dark fill colors (luminance < 50%): white text
- Light fill colors (luminance >= 50%): black text
- Font: small, monospace-style

### Locator Thumbnail

For multi-baseplate mosaics, a small (30x30mm) version of the full mosaic grid in the top-right corner, with the current section highlighted (brighter) and other sections dimmed (grayed out or lower opacity border overlay).

For single-baseplate mosaics, skip the locator.

## Architecture

### New file: `src/lib/instructionGenerator.ts`

Inputs: `MosaicResult` (from `mosaicEngine.ts`) -- contains `colorGrid`, `ldrawColorGrid`, `partsList`, `config`, `optimized`.

Responsibilities:
1. Assign sequential color numbers to unique colors in the mosaic
2. Compute per-section grids (split the global grid by baseplate boundaries)
3. Generate the PDF using jsPDF

```typescript
  // 3. Render pages via jsPDF

}
```

### Integration in MosaicCreator.tsx

Add a third download button next to the existing "Download .ldr" and "Download BrickLink XML" buttons. The button calls `generateInstructionsPDF(result)` and triggers a download of the resulting Blob as `mosaic-instructions.pdf`.

## Coordinate Math for Section Extraction

The baseplate layout (`config.baseplateLayout`) tells us how many baseplates tile the mosaic:
- `cols` baseplates across, `rows` baseplates down
- Each baseplate is `sizeStuds` x `sizeStuds`

For baseplate at grid position (bpRow, bpCol), the sub-grid is:
```
startRow = bpRow * sizeStuds
endRow = min(startRow + sizeStuds, heightStuds)
startCol = bpCol * sizeStuds
endCol = min(startCol + sizeStuds, widthStuds)
```

## Text Contrast

To decide white vs black text on a colored cell:
```typescript
function textColorForBackground(hex: string): string {
  // Relative luminance formula (WCAG)
  const r = parseInt(hex.slice(1,3), 16) / 255;
  const g = parseInt(hex.slice(3,5), 16) / 255;
  const b = parseInt(hex.slice(5,7), 16) / 255;
  const luminance = 0.299 * r + 0.587 * g + 0.114 * b;
  return luminance > 0.5 ? '#000000' : '#FFFFFF';
}
```

Already have RGB values in the LEGO_PALETTE, so this is trivial.

## Open Questions

1. **Cell size for 48-stud baseplates**: At A4 with 15mm margins, usable width is 180mm. 180/48 = 3.75mm per cell. A 5pt font (~1.76mm) fits, but it's tight. Could offer landscape orientation for wide baseplates, or split into halves. Need to test readability during implementation.

2. **Optimized pieces in instructions**: When "Minimize Pieces" is on, the grid has mixed-size pieces. The section page could either (a) show the 1x1 color grid with numbers (ignoring piece boundaries), letting the LDR file handle actual piece layout, or (b) draw piece boundaries on the grid. Option (a) is simpler and still useful -- the user sees what color goes where, and the LDR file in Studio shows exact piece placement. Option (b) is more informative but significantly more complex to render. Recommend starting with (a).

3. **jspdf-autotable**: The BOM page is a simple table. Could use the jspdf-autotable plugin for nice formatting, or just draw it manually with `doc.text()` and lines. Manual is fine for a simple table -- avoid the extra dependency unless the table gets complex.
